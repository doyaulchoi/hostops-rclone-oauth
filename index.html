Personal backup utility · Updated November 1, 2026

Encrypted Google Drive backups for one operator

This site describes a private rclone backup workflow used by one operator to keep and verify recovery copies. It is not a hosted, multi-user backup service. Production OAuth publication lets any Google account attempt consent, but this software is configured for one operator. Visiting this site does not create an account or give anyone access to a backup.

Read the Google Drive access request

The OAuth client requests Google’s full Drive scope, https://www.googleapis.com/auth/drive. Google may therefore let the authorized client read and manage all files in the connected Drive account. The current backup software is configured to use a dedicated backup area for encrypted backup upload, listing, download, and restore checks. The permission itself is broader than that configured use.

What the workflow does

It creates allowlisted database and host-operations backups, encrypts backup file contents and file names locally with rclone crypt, uploads them to the operator’s Google Drive, and downloads them again to check the copy and test restoration. Folder names and some file metadata remain visible to Google Drive.

The OAuth refresh token and rclone encryption credentials stay in a host-local configuration file. They are excluded from the backup. Local recovery copies are plaintext while staged and are removed only after the encrypted Drive copy passes readback and restore verification; an unverified run is retained for investigation.

Policies

Read the Privacy Policy for the data handled, storage, encryption, and retention details, and the Terms of Use for the personal-use limits.

Questions or privacy requests can be sent to the developer contact shown on the OAuth consent screen. Do not send backup files, passwords, or OAuth credentials in a support request.
